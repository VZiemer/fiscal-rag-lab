# Contributing

1. Read `README.md`, `AGENTS.md` and the ADRs before proposing a major change.
2. Open an issue linking the relevant task and expected outcome.
3. Keep commits scoped to a task (for example, `feat(vector): add exact top-k search`).
4. Add unit tests and, for retrieval changes, evaluation/benchmark cases.
5. Document major technology changes as a proposed ADR before replacing components.
6. Do not commit official document dumps until their redistribution terms are established.
